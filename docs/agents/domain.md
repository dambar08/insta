# Domain Docs

This is a single-context repository. Domain terms belong in the root `GLOSSARY.md`; architectural decisions belong in `docs/adr/`.

Before exploring a domain area, read the glossary and relevant ADRs when those files exist. If they do not exist, proceed without flagging their absence; add them when domain terms or architectural decisions are actually resolved.

Use glossary terms in issue titles, test names, and proposals. Surface conflicts with existing ADRs rather than silently overriding them.
